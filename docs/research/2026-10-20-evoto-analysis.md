# Evoto 기능 역공학 분석

작성 2026-10-20. 비교 기준: [인물 보정 B~F 설계](../superpowers/specs/2026-10-15-beauty-b-to-f-design.md) 이후의 main(1.2.0).

## 사람이 확인할 것

### 어떻게 관찰했나

| 방법 | 한 것 | 한계 |
|---|---|---|
| 기능 페이지 텍스트 | 인물·배경·색·워크플로 페이지 66개 본문 수집·요약 | 마케팅 문구라 알고리즘은 직접 안 나옴. FAQ는 질문만 수집됨 |
| 보정 전후 이미지 픽셀 비교 | 공개 전후 이미지 약 70쌍을 받아 바뀐 면적·밝기 변화·색 변화·고주파(질감) 보존율을 계산하고 차이 지도를 눈으로 확인 | Evoto가 고른 샘플이라 최선의 결과만 있음. 슬라이더 값별 변화는 못 봄 |
| 앱 화면 안내 이미지 | 페이지에 실린 Evoto 데스크톱 패널 화면에서 슬라이더 이름·구성 확인 | 일부 이미지는 서버가 내려받기를 막음(403) |
| Evoto 데스크톱 앱 직접 조작 | 로그인·첫 화면까지 진행 후 중단 | 앱이 앞에 있어야만 입력을 받아 사용자 작업을 방해함. 사용자 요청으로 멈춤 |

슬라이더를 단계별로 움직여 보는 관찰은 하지 않았다. 아래 "추론"은 전후 이미지·화면 안내·문구에서 끌어낸 것이다.

### 핵심 발견

1. **조작 모델은 "자동 감지 + 강도 슬라이더 하나"가 기본이다.** 다크서클·팔자주름·미간 주름은 각각 슬라이더 하나(0~100)다. 피부 보정은 "매끄러운 질감" 아래에 "주파수 분리"를 펼치면 고주파·저주파 슬라이더가 따로 나온다. 얼굴 외에 "바디 피부" 슬라이더가 따로 있다.
2. **피부 계열이 가장 촘촘하다.** 잡티 제거 패널 안에 다크서클·팔자(마리오네트) 주름·미간 주름·주름이 나란히 있다. 전후 차이 지도를 보면 모두 해당 부위의 국소 밝기만 올린다(면적 1~4%, 밝아진 픽셀 55~80%). 질감(고주파)은 0.9~1.0배로 거의 그대로다. 생성형이 아니라 "그 부위의 저·중주파 어두움을 주변 피부 수준으로 끌어올리는" 보정으로 추론한다.
3. **주파수 분리의 저주파 쪽은 얼룩 고르기다.** 전후 비교에서 붉은 반점·색 얼룩 부위의 색(붉은기)이 주변 평균으로 모이고 밝기가 조금 오른다(밝아짐 64%, 붉은기 감소). 지금 mellow-photo의 피부 보정은 중주파만 줄이고 저주파 색 얼룩은 건드리지 않는다.
4. **피부색 변경은 얼굴만이 아니라 보이는 피부 전체에 걸린다.** 단체 사진에서 얼굴·팔·배의 피부만 밝아지고(+6.6%) 붉은기가 줄었다. 옷·배경은 그대로다.
5. **캐치라이트는 눈동자에 하이라이트를 그려 넣는다.** 모양 프리셋(일반·실내 각 6종)을 고르고 양·가로·세로·회전·좌우 반전을 왼눈·오른눈 따로(연결 가능) 조정한다. 두 눈에 같은 방향으로 찍혀 광원 하나처럼 보인다.
6. **여러 장 처리는 "한 장 보정 → 동기화"다.** 동기화 버튼 옆 톱니에서 무엇을 동기화할지 고른다. mellow-photo의 "전체 사진에 적용"은 고를 수 없고 전부 복사한다.
7. **Evoto 기능의 상당수는 생성형이라 지금 구조로는 못 따라 한다.** 눈 뜨기, 시선, 표정, 미소, 가르마 채우기, 안경 반사 제거, 문신·수염·잔머리 제거, 배경 확장, 업스케일이 여기 해당한다. 헤어 윤기·흰머리·머리색은 머리카락 영역이 있어야 하는데 Apple Vision에는 일반 사진용 머리카락 분할이 없다.

### mellow-photo와의 차이

| Evoto 기능 | mellow-photo 지금 | 지금 구조(Vision + Core Image, 모델 없음)로 가능한가 |
|---|---|---|
| 다크서클 | 없음(B~F 범위 밖) | 가능. 눈 랜드마크 아래 띠 + 볼 기준색으로 밝기·색 보정 |
| 팔자·마리오네트·미간 주름 | 없음(B~F 범위 밖) | 가능. 코·입·눈썹 랜드마크로 주름 띠를 정하고 국소 밝기 들어 올림 |
| 피부 저주파 얼룩 고르기 | 중주파 매끄럽게만 있음 | 가능. 기존 3대역 분리의 저주파 색을 피부 평균으로 당김 |
| 붉은기(맑게↔혈색) | 없음 | 가능. 피부 마스크 안 붉은 정도를 양방향으로 |
| 피부 밝기·톤(몸 포함) | 없음(B~F "미백" 범위 밖) | 가능. 인물 마스크 × 피부색 가중치. 얼굴이 없으면 기준색이 없어 건너뜀 |
| 바디 피부 매끄럽게 | 얼굴만 | 가능. 같은 마스크로 기존 주파수 분리 적용 |
| 번들거림(매트) | 없음(B~F 범위 밖) | 가능. 피부 안 밝고 채도 낮은 반사 영역만 눌러 줌 |
| 캐치라이트 | 없음(눈 또렷하게만) | 가능. 눈동자 랜드마크 위에 부드러운 하이라이트 그리기 |
| 이중 턱 | 없음 | 부분 가능. 턱선 아래 그림자 조정 + 기존 이동량 지도. 결과 확신 낮음 |
| 그레인·글로우 효과 | 없음 | 가능. Core Image 기본 필터 |
| 선택 동기화 | 전부 복사만 | 가능. 렌더링이 아니라 편집·라이브러리 변경 |
| 분할 전후 비교 | 전체 토글만 | 가능. 앱 화면 변경 |
| 헤어(윤기·흰머리·색·잔머리) | 없음 | 불가. 머리카락 분할 모델이 필요 |
| 눈 뜨기·표정·시선·문신·안경 반사·배경 확장 | 없음 | 불가. 생성 모델이 필요 |

### 권장 적용 범위 (사용자가 정함)

권장은 피부 계열을 한 단계(G)로 묶는 것이다. B~F 때 "사용자가 고르지 않음"으로 빼 둔 항목이 Evoto에서 가장 촘촘한 영역이고, 모두 기존 피부 단계·마스크 위에 얹을 수 있다.

| 우선 | 묶음 | 들어가는 것 |
|---|---|---|
| 1 | 피부 정밀 | 다크서클, 팔자주름, 미간 주름, 피부 얼룩 고르기, 붉은기(양방향), 번들거림 |
| 2 | 몸 피부·톤 | 피부 밝기, 피부 톤(따뜻↔차가움), 바디 피부 매끄럽게 |
| 3 | 눈 빛 | 캐치라이트(모양 몇 종 + 양·위치) |
| 4 | 효과·작업 흐름 | 그레인, 글로우, 선택 동기화, 분할 전후 비교 |

실제 범위는 사용자 결정 뒤 스펙(`docs/superpowers/specs/`)에 적는다.

### 위험

- **전후 샘플이 최선의 결과다.** 실제 사진에서 같은 품질을 낸다는 보장이 없다. 구현 뒤 같은 입력(`shared/fixtures/demo-portrait.png`)으로 비교한다.
- **주름 위치는 추정이다.** Vision 랜드마크에는 주름선이 없어 코 날개·입꼬리·눈썹 사이 점으로 띠를 그린다. 얼굴이 많이 돌아가면 띠가 어긋날 수 있다.
- **몸 피부는 얼굴 기준색에 기댄다.** 얼굴이 없거나 조명이 얼굴과 몸에 다르게 떨어지면 피부 판별이 흔들린다.

### 사용자 조치

- 적용 범위·우선순위 결정.
- 구현 뒤 기기에서 실제 인물 사진으로 강도 확인(자동 테스트로 품질은 판정할 수 없음).

### Evoto 패널 구성 (화면 안내 이미지에서 읽음)

- 피부 보정: `매끄러운 질감` 0~100, 그 아래 `주파수 분리` 0~100 펼침 → `고주파`(가운데 기준 양방향) · `저주파` 0~100. `바디 피부` 0~100 별도.
- 잡티 제거(Blemish Removal): `Dark Circles` 0~100, `Marionette Lines` 0~100, 미간 주름·주름 각각 슬라이더.
- 캐치라이트: 탭 `General`/`Indoors`, 모양 `None`+6종, `Amount`·`Horizontal`·`Vertical`·`Rotate`·`Flip Horizontal` 각각 L/R과 연결 토글.
- 동기화: `현재 프리셋 저장`, `동기화`, 톱니(동기화 항목 선택).

### 수집물 위치

원본 텍스트·이미지·차이 지도는 저장소에 넣지 않았다. 세션 스크래치패드(`evoto/`, `evimg/`, `diff/`)에만 있고 세션이 끝나면 사라진다.
