# 인물 효과와 부위 선택 보정 후속 설계

## 사람이 확인할 것

사용자는 자동과 인물 원터치 모두 밝기만 달라지고 인물 보정이 보이지 않는다고 보고했다.
목표는 기존 사진의 피부·잡티·윤곽을 실제로 다듬고 원하는 부위를 눌러 해당 보정에 도달하는 흐름이다.
서버 이미지 생성 API를 사용하지 않고 사진 처리를 기기 내부에서 수행한다.

| 결정 | 이유 | 변경 비용 |
|---|---|---|
| 밝기만 바꾼 결과를 인물 효과 성공으로 인정하지 않는다 | 기존 변경 픽셀 하한은 밝기만으로도 통과할 수 있었다 | 검사 보강, 중간 |
| 자동·인물 원터치의 실제 앱 적용 경로와 미리보기 결과를 측정한다 | 직접 레시피 렌더 검사만으로 버튼 동작을 보증하지 못한다 | 중간 |
| 기존 피부 원터치는 얼굴형·체형을 유지한다 | 기존 계약과 수동 편집 보호를 보존한다 | 작음 |
| 이중턱·부유방은 명시적으로 선택하는 도구로 빠르게 노출한다 | 사용자가 원하는 윤곽 보정을 찾을 수 있어야 한다 | 중간 |
| 부위 클릭은 사람과 해당 도구를 고르고, 보정값은 사용자가 조정한다 | 클릭 위치를 잘못 해석해 사진을 곧바로 변형하지 않는다 | 중간 |
| 강도·비교·되돌리기와 보정 불가 이유를 같은 흐름에서 제공한다 | 효과가 약하거나 분석 조건이 안 맞는 경우를 구분한다 | 중간 |
| 개인 수동 값을 원터치가 몰래 지우지 않는다 | 기존 사람별 편집을 보존한다 | 큼 |
| 남성·여성 그룹의 적용 인원을 표시하고 빈 그룹의 인물 조정을 막는다 | 적용 대상 없이 값과 기록만 바뀌는 결함이 사용자 조건에서 재현됐다 | 중간 |
| 기능 이름만 존재하거나 합성 화면 검사를 통과한 경우 완료로 표시하지 않는다 | 실제 사진의 보정 효과와 보호 범위를 별도 검증한다 | 중간 |

현재 이중턱·부유방 엔진과 슬라이더는 이미 존재하지만 빠른 보정에 직접 연결되지 않았고, 캔버스 클릭은 사람 선택만 지원한다.
이 기능들은 접근성을 먼저 보완하되 실제 효과 검사를 유지한다.
아래 미구현 항목까지 완료한 것으로 주장하지 않는다.

기능별 현황과 미구현 항목은 아래 [기능 추적표](#기능-추적표)에 기록한다. 별도 검증 앱으로 확인하며 기존 TestFlight 앱과 사진은 보존한다. 수용한 수정만 기존 TestFlight 배포 경로로 전달한다.

### 독립 검수 추가 계약

- clean demo의 새 관측값으로 성공 문턱을 사후 조정하지 않는다. 변경 픽셀 비율과 중주파 분산 감소만으로 수용하지 않는다. 해당 결함의 개선과 정상 미세 질감 보존, 눈·입·배경 보호를 각 사진·각 버튼별로 확인한다.
- brightness-only와 skin-tone-only 대조는 두 앱 경로에서 모두 거절돼야 한다. texture-only 절제 결과는 실제 full-output 품질의 대용으로 쓰지 않는다.
- 개인 override의 명시적 0·비영·일부 키와 그룹·성별 미지정·여러 사람을 교차 검사한다. 기존값 때문에 가려지는 경우를 안내하고 자동 삭제하지 않는다. 사용자가 명시적으로 재설정한 경우 그 사람/그 키만 한 번에 되돌린다.
- 부위 선택은 recipe·undo·dirty·저장 상태를 변경하지 않는다. 대상 전환 전에 기존 slider drag를 종료하며 늦은 분석 결과와 A→B→A 전환이 다른 사람을 변경하지 않는다.
- crop/회전/flip뿐 아니라 zoom/pan/letterbox·분할 비교 양쪽과 기존 비선형 얼굴/몸/local warp 후 위치를 확인한다. geometry inverse만으로 워프 후 위치가 정확하다고 가정하지 않는다. 불확실한 경우 값을 바꾸지 않고 명시적 대상 선택으로 안내한다.
- 기존 턱 최대 얼굴폭4.5%·입술0.05 preview px·턱 그늘12/255 및 모든 shape 상하한을 유지한다. 마스크/랜드마크/옆선이 없으면 전역 또는 인접 부위로 대체하지 않는다.
- 합성/생성 fixture 성공, 실제 촬영 사진 일반화, 사용자가 보고한 증상 해결은 구분해서 기록한다.

### 사용자 재현 환경 확인

사용자가 2026-10-28 두 버튼 모두에서 증상이 있었으며 사용 기기는 iPhone 또는 iPad라고 답했다.
Mac 데모의 효과 관측과 iOS 실사용 결함 해결을 구분한다.
같은 실제 앱 경로·사진·대조·지표를 iOS에서 실행해야 한다.
iOS 시뮬레이터 통과 역시 실제 사용자 기기의 동일 사진 해결을 자동 보장하지 않는다.
비선형 얼굴/몸/수동 워프 이후 역변환이 없는 상태에서는 사진 클릭 선택을 비활성화하고 부위 목록을 제공한다.
이때 기존 보정값이나 원본은 바꾸지 않는다.

추가 확인: 사용자는 iPhone에서만 실행했으며 상세 슬라이더를 직접 조절해도 인물 효과는 거의 없고 배경색·색감 위주로 달라졌다고 설명했다.
따라서 원터치 묶음이나 개인 override만을 주원인으로 확정하지 않는다.
독립 정적 검수에서 iOS/Mac의 공유 커널·색 공간·출력 경로는 같고, 실제 기기 메모리에 따른 미리보기 크기와 Vision 실행 환경이 다름을 확인했다.
커널 초기화 실패가 조용히 색 보정만 남기는 fallback 경로는 확인되지 않았다.
연결된 실제 iPhone의 테스트는 별도 QA bundle identifier와 독립 컨테이너로만 수행하며 기존 TestFlight 앱과 사용자 사진 데이터를 덮어쓰지 않는다.

### 현재 진단 입력의 출처

`docs/store-assets/README.md`에 따르면 `demo-portrait.png`는 2026-10-13 내장 image_gen으로 만든 가상 성인 인물이다.
현재 진단은 이 기존 사진 형태 데모와 실제 Vision·실제 앱 경로를 사용한다.
실제 촬영 사진이나 사용자 사진을 대상으로 한 일반화 검증으로 표시하지 않는다.
이번 작업에서 새 이미지를 생성하거나 사용자 사진을 외부로 전송하지 않았다.
초기 새 테스트 주석의 '실제 공개 사진' 표현은 이 출처와 맞지 않아 정정한다.

### 실제 기기와 빈 성별 그룹 진단

사용자는 iPhone 15 Pro에서 상세 조정의 대상을 남성 그룹 또는 여성 그룹으로 선택했다고 확인했다.
등록 승인을 받은 해당 기기의 iOS 26.6.2에서 별도 QA 앱으로 기존 생성 데모의 AppModel→Vision→미리보기 경로를 실행했다.
인물 원터치 얼굴 변화율 19.2183%, 자동 25.7950%, 질감 단독 영역 21,035픽셀·변화율 15.9306%를 관측했다.
검수자는 별도로 PNG와 고정 소스의 해시를 대조했다. 보이는 PhotoCanvas·상세 슬라이더 UI나 사용자 촬영 사진의 해결 판정은 아니다.
iOS 27 시뮬레이터에서는 같은 입력의 Vision 랜드마크가 반복 실행마다 달라졌다. 이 현상을 근거로 실제 기기 분석기나 보정 강도를 바꾸지 않는다.

성별 추정기가 없는 실제 조립에서는 얼굴 성별이 미지정이다. 성별 그룹 선택만으로 사람의 성별을 지정하지 않는다.
기존 AppModel은 빈 성별 그룹에도 원터치와 상세 값을 기록하고, 렌더러는 미지정 얼굴에 그 그룹을 적용하지 않는다.
제품 worktree의 회귀 검사에서 남녀 그룹 각각 `targets=0`, `documentChanged=true`, `outputIdentical=true`를 확인했고 무효 조작의 문서·이력 불변 검사가 실패했다(`/tmp/portrait-target-safety-red.log`).

수정 계약:

- 그룹 인원은 렌더러와 같은 사람 매칭·유효 성별로 센다. 짝 없는 저장 기록을 현재 대상에 포함하지 않는다.
- 빈 그룹에서는 얼굴 대상 조정의 UI와 AppModel 쓰기를 함께 막고 전체·개인 선택을 제공한다. 거절된 조작은 문서·이력·저장을 바꾸지 않는다.
- 대상 변경만으로 성별을 지정하거나 레시피를 변경하지 않는다. 개인 값과 미연결 기록을 삭제하지 않는다.
- 전역 몸 피부·색 조정과 전체 원터치는 유지한다. 그룹 조정과 무관하게 동작하는 제어를 함께 끄지 않는다.
- 명시적 초기화·실행 취소와 도메인의 프리셋용 그룹 저장 계약은 유지한다. 기존 빈 그룹 편집 허용 테스트는 바뀐 AppModel 적용 가능성 계약을 설명하고, 유효한 그룹의 양성 사례를 별도로 보존한다.
- 드래그 도중 대상 전환·늦은 분석·사진 전환에서 다른 대상의 값이 바뀌지 않아야 한다.
- 전역 빠른 보정의 `.portrait`와 `.automatic`은 전체를 대상으로 하므로 이 결함만으로 두 버튼의 실사용 증상이 해결됐다고 하지 않는다.

첫 중간 검수: 제품 worktree의 `test-output/portrait-utilities/empty-group-checkpoint/manifest.json`에 고정된 17개 파일과 패치 해시를 검수자가 확인했다.
보정 버튼의 두 빈 그룹 회귀는 정정된 RED 4건 실패에서 GREEN 0건 실패로 바뀌었다. RED 전체 소스가 별도 고정되어 있지 않아 전체 소스 동일성을 인증한 기록은 아니다.
강도 0·메이크업 해제의 빈 값 처리와 상세 조정·전역 몸 피부·초기화·매칭·드래그 경계는 추가 검사가 필요하므로 최종 승인이 아니다.
검수 기록은 `test-output/portrait-utilities-independent-review/empty-group-checkpoint-review.json`이며 제품 소스와 기기에는 변경을 가하지 않았다.

중간 v2에서는 빈 값의 강도 0·메이크업 해제 검사를 RED 직전 고정한 테스트와 같은 파일로 실행했다. 3개 실패가 사라지고 기존 AppModel 검사 포함 81개가 통과했으며, 검수자는 테스트 조건 완화가 없음을 확인했다.
기존 그룹 편집 검사는 실제 매칭된 사람에 성별을 지정하는 준비 과정으로 바꾸고, 과거 빈 그룹에 남은 값은 도메인 API로 넣어 복원·초기화 계약을 보존했다.
v3 구현자 검사에는 거절된 드래그 종료·중복 종료, 드래그 중 인원 0명 전환, 미연결 기록 제외와 수동 성별 우선, 초기화 undo/redo/재불러오기·개인 값 보존을 더했다. 85개 검사 실패 0건이며 검수자가 고정 17개 파일·패치·실행 로그를 대조해 해당 모델 계약을 승인했다. 검수자의 독립 재실행이나 실제 화면 승인까지 포함하지 않는다.

### 인계와 배포 전 확인

첫 제품 고정본은 `e1bbe3e`다. 구현자 실행에서는 기존 AppModel 76개와 대상·부위 검사 14개, 총 90개가 통과했다. 독립 실행과 실기기 화면 검사는 별도로 진행한다.
