# 원터치 주 버튼의 개인 조정 충돌 해결

## 사람이 확인할 것

사용자는 1.6.1 배포 안내 후에도 인물이 달라지지 않는다고 보고했고, 이번에도 ‘원터치 보정’만 눌렀다고 확인했다.
기본 버튼은 개인 설정을 보호하지만 교체 동작은 별도 버튼에 있어 사용자가 적용 차이를 알아내야 했다.
기존 개인 설정이 보호되는 경우에는 주 버튼에서 바로 선택하도록 고친다.
이번 수정은 적용 흐름 개선이며 피부 엔진의 강도 증가나 실제 사진 품질 수용을 뜻하지 않는다.

| 결정 | 이유 | 변경 비용 |
|---|---|---|
| 주 버튼에서 개인 설정 충돌을 즉시 표시한다 | 얼굴 변화가 없는 이유와 적용 방법을 같은 흐름에서 제공한다 | 중간 |
| 선택하기 전에는 사진을 바꾸지 않는다 | 얼굴은 유지하면서 몸 밝기부터 바뀌는 부분 적용을 피한다 | 중간 |
| 기존 조정 유지와 해당 인물 항목 교체를 명시적으로 선택한다 | 다른 편집을 몰래 지우지 않으면서 요청 강도를 적용한다 | 중간 |
| 얼굴의 변경 항목 수와 적용 인원을 구분한다 | 항목 수를 사람 수로 오해하지 않게 한다 | 작음 |
| 사진이나 대상이 바뀌면 열린 선택은 무효다 | 이전 사진의 요청이 다른 사람에게 적용되는 것을 막는다 | 중간 |
| 밝기·밤 색감·배경·형태와 수용 기준을 유지한다 | 버튼 흐름 수정과 렌더 품질 변경을 분리한다 | 큼 |

기기 내부에서만 처리한다.
개발과 독립 검수를 분리하며 수용한 수정만 기존 배포 경로로 전달한다.
새 목적별 UI와 옷 주름 연구는 이 결함 수정 뒤 이어간다.
사용자의 iPhone 화면 유지나 개인 사진 재전송을 이번 UI 검사에 요구하지 않는다.

## 에이전트 참조

- 기준 main `6c96d474a7bf954ec36fe50ce992658dae51454c`, 1.6.1(14.1).
- 구현 `/root/implementer`, worktree `.claude/worktrees/portrait-effect-followup`.
- 독립 검수 `/root/reviewer`, 제품 소스 수정과 기기 조작 금지.
- root는 설계·인계·통합·배포만 담당한다.

### 동작 계약

1. `OneTouchRow`의 Quick 전체와 Beauty 현재 대상에 같은 진입 함수를 사용한다.
2. 전체/그룹의 양의 강도 요청에 `protectedPersonal` 항목이 있으면 선택 화면을 연다.
3. 부분적으로 변경 가능한 경우도 포함한다.
4. 선택 화면을 여는 동작과 취소는 문서·undo·dirty·저장·렌더를 바꾸지 않는다.
5. 유지 선택은 기존 default semantics, 교체 선택은 기존 explicit ready-key semantics를 그대로 사용한다.
6. 개인·얼굴 대상의 기존 직접 재적용 의미와 강도 0의 legacy clear/explicit neutral 의미를 변경하지 않는다.
7. 교체 범위는 그 요청 대상의 준비된 OneTouch 키뿐이다.
8. 색·배경·몸 형태·턱 형태·다른 사람·미연결 기록·준비되지 않은 항목을 삭제하거나 초기화하지 않는다.
9. 선택 요청은 photoID, target, strength, context, analysis generation, base document 또는 이에 준하는 기존 plan 불변식에 결합한다.
10. 선택 중 사진/대상/분석/레시피/강도 변경이나 A→B→A 이후 옛 요청을 적용하지 않는다.
11. stale 요청은 무효 안내 후 새 주 버튼 요청을 요구한다.
12. 새 시도·취소·no-op에서 이전 완료 표시를 새 시도의 성공으로 남기지 않는다.
13. 적용 후 동일 요청 재확인은 중복 저장·이력을 만들지 않는다.
14. 적용 완료는 대응하는 저장·미리보기 성공 이후에만 표시한다.
15. 기존 별도 교체 경로는 유지하며 동일 실제 API로 연결한다.

선택 화면 진입에는 자동 편집 종료를 수행하는 기존 submit 함수를 재사용하지 않는다.
다른 상세 슬라이더의 저장 대기가 있으면 자동으로 저장하지 않고 해당 편집을 먼저 끝내도록 안내한다.
기본 적용과 개인 교체 계획은 같은 snapshot에서 계산한다.
개인 교체는 기본 적용을 먼저 한 뒤 덧씌우는 합성 작업이 아니며 전역·그룹·몸 피부 값을 그대로 보존한다.
각 선택에서 얼굴의 실효 변경 인원과 키 수, 유지 인원, 몸 피부 변경 여부를 구분해 알린다.
현재 요청값을 바꾸었다가 다시 되돌리는 강도 A→B→A 역시 세대 변경으로 처리한다.

### 검증

- 실제 주 버튼 진입 함수의 RED→GREEN으로 선택 전 mutation0을 확인한다.
- 유지·교체·취소와 일부 보호/전부 보호, 양의 강도·0, 개인·전체·성별 그룹을 교차한다.
- explicit 개인 0·비영·일부 키, 준비되지 않은 키, 다른 사람과 기존 색/배경/형태 보존을 확인한다.
- confirmation 시점의 사진/대상/분석/강도/레시피 stale와 A→B→A를 거절한다.
- 저장·렌더 실패, 중복 확인, 한 번의 undo/redo/reload, 이전 success 표시의 수명을 확인한다.
- 기존 합성 QA fixture로 Quick/Beauty의 실제 주 버튼→선택 화면→교체→보이는 완료·비교·undo를 시뮬레이터에서 수행한다.
- 선택 화면의 제목·보호 인원·변경 범위·유지/교체/취소가 작은 화면에서도 보이고 접근 가능한지 확인한다.
- 합성 UI 통과를 자연 사진의 피부 개선이나 사용자 원본 해결로 주장하지 않는다.
- 기존 수용 문턱과 렌더 코드는 변경하지 않는다.

### 서비스와 자료

구현자가 테스트 실행과 종료를 책임진다.
검수자는 별도 작업 공간에서 고정된 변경을 검토하고 독립 재실행한다.
사용자 원본·설정·파생 이미지는 Git·CI·외부 모델에 포함하지 않는다.
이전 로컬 임시 결과가 없으면 다시 검증했다고 기록하지 않는다.

2026-10-29 확인에서 이전 사용자 원본 첨부의 임시 경로와 좁힌 설정 파일은 존재하지 않았다.
따라서 이번 실행의 원본 재현 근거로 재사용하지 않는다.
기존 증거의 서술과 새 합성 검사의 결과를 구분한다.
