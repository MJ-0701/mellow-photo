# 실제 사용 사진에서 인물 보정 효과 부족 재진단

## 사람이 확인할 것

1.6.0 사용 후 사용자는 원본·보정본 화면을 제공하며 밝기 외에 원하는 인물 수정이 보이지 않는다고 다시 보고했다.
화면에는 전체 선택, 여성 그룹 1명, 적용 대상 1명, 강도 1.00이 표시되어 있다.
빈 그룹 수정이나 화면 이동 검사의 통과로 이 증상의 해결을 주장하지 않는다.

| 결정 | 이유 | 변경 비용 |
|---|---|---|
| 실제 결함 개선과 밝기·색·배경 변화를 분리해 판정한다 | 화면 전체의 변화량은 원하는 인물 정리의 증거가 아니다 | 중간 |
| 원터치의 피부 정리와 윤곽·이중턱·체형 적용 범위를 먼저 바로잡는다 | 현재 원터치에는 형태 보정이 포함되지 않는다 | 큼 |
| 표시 강도와 각 사람의 실제 적용값을 구분한다 | 개인별 값이 전체 값보다 우선할 수 있다 | 중간 |
| 설명·경고만 고치고 증상이 해결됐다고 배포하지 않는다 | 이전의 접근성 개선만으로 사용자 목적을 달성하지 못했다 | 중간 |
| 기존 효과 하한과 보호 상한을 유지한다 | 색이나 강도를 무작정 높여 통과시키지 않는다 | 큼 |

사용자가 제공한 원본과 승인된 범위의 실제 저장 설정으로 증상을 재현했다.
전체 강도를 올려도 기존 개인 설정이 얼굴 보정값을 유지하고 몸 피부 밝기만 바뀌는 것이 확인됐다.
전체·그룹의 기본 적용은 개인 설정을 보존하며, 해당 인물의 개인 설정까지 바꾸는 명시적 적용을 별도로 제공한다.
사람을 직접 선택한 원터치는 기존처럼 그 사람의 설정을 다시 적용한다.
같은 사진의 수정 결과와 독립 검수가 통과하기 전에는 해결 완료나 배포 완료로 표시하지 않는다.
기기 내 처리, 사용자 사진 비공개, 구현·검수 역할 분리를 유지한다.

## 에이전트 참조

- 기준 제품: `dde9952eb1e47cd44520caf7a1ae07f0d2f170df`, 1.6.0 (13.1).
- 구현 담당: `/root/implementer`, `codex/portrait-effect-followup`.
- 독립 검수: `/root/reviewer`, 제품 소스 수정과 실기기 조작 없음.
- 루트: 증상·설계 기록과 인계, 제품 코드 구현 없음.
- 실패한 옷 주름 연구 worktree와 기존 사용자 사진·앱 컨테이너를 변경하지 않는다.
- 사용자 제공 사진과 파생 검사 입력·출력은 Git, 원격 CI, 외부 API에 올리지 않는다.

### 관측된 사실

- 두 화면의 원본/보정본 표시와 선택 사진은 대응한다. 사용자는 추가 질문에 '원터치 보정만 누름'이라고 확인했다. 다른 기능을 함께 사용했다고 가정하지 않는다. 당시 저장 레시피와 렌더 세대는 아직 확인되지 않았다.
- 보정본에서는 피부 밝기, 입술 색, 배경 흐림과 명암 변화가 눈에 띈다.
- 화면의 개인 칩에 별도 설정 표시가 있다. 해당 키와 값은 화면만으로 판정할 수 없다.
- `OneTouchBundle.keys`는 피부·눈/입 기능·일부 메이크업이며 얼굴형·체형 키를 제외한다.
- 전체 원터치 강도는 해당 층의 표시이며 `PortraitResolver`의 최종 개인 값과 항상 같은 것은 아니다.
- 원터치 묶음 자체는 전역 색이나 배경 흐림을 쓰지 않는다. 사용자가 보고한 단일 조작과 실제 화면 결과의 차이를 편집 진입·저장값·렌더·비교 표시 경로에서 확인해야 한다. 이 차이를 사용자 조작 탓으로 설명하지 않는다.

### 이전 검사의 독립 재감사

- 얼굴 사각형의 RGB 변화율은 피부 톤·립색 변화도 통과시킨다.
- 질감 대역의 분산 하한은 손상 방지 검사이며 국소 결함 개선 하한이 아니다.
- 전체 출력과 전역 조정 대조의 차이에는 피부 미백·메이크업 변화가 남을 수 있다.
- 동일 대조 이미지를 자신과 비교한 `brightnessOnly` 음성 대조는 항상 0이어서 실제 밝기 변화의 오판 가능성을 검사하지 않는다.
- 질감 단독 출력의 RMS가 0보다 크다는 조건은 경로 연결 확인이며 최종 출력의 결함 개선을 보장하지 않는다.
- 기존 잡티·그늘 복원 및 이중턱·체형 효과/보호 검사는 유지한다. 이를 실제 앱의 최종 출력 평가와 연결한다.

### 원터치 편의성의 후속 설계 조건

피부·턱밑·옆선 등 명시적인 목적을 선택한 뒤 한 번의 적용으로 해당 값을 실제로 쓰고 한 번의 실행 취소로 되돌리는 흐름을 검토한다.
목적 선택 자체가 사용자의 의사표시이며 반복 확인 창은 요구하지 않는다.
검출 가능한 항목과 사람, 기존 편집 보호로 유지되는 항목, 실제 적용 범위를 구분한다.
미검출 또는 좌표 불확실 항목을 색·배경 효과로 대신하지 않는다.
모든 항목이 미적용이면 보정 완료로 표시하지 않는다.
이 조건의 내부 적용 기능은 후속 커밋에서 구현·좁은 검수를 완료했으나 제품 UI와 사진 품질은 아직 수용하지 않았다.

### 재현 관문

1. 실제 AppModel 편집 진입점과 렌더를 연결한 실행 가능한 실패 루프를 먼저 만든다.
2. 축소 원본 화면 입력의 한계를 표시하고, 같은 입력에서 밝기·색·배경만 바꾼 대조를 인물 개선으로 통과시키지 않는다.
3. 피부 질감·국소 결함·그늘 개선과 이목구비·배경·정상 질감 보호를 별도로 관측한다.
4. 원터치가 형태를 쓰지 않는 현재 계약과 사용자가 기대하는 이중턱·윤곽 정리를 구분한다.
5. 전체·그룹·개인 우선순위, 개인 명시값 0과 비영 값, 기존 편집이 있는 사진을 포함한다.
6. 실패 루프가 확인된 뒤 반증 가능한 가설을 순위와 함께 보고하고 한 변수씩 검사한다.
7. 수정 후에도 같은 증상 입력과 기존 보호 검사를 통과해야 한다. 사진이 없는 생성 fixture 통과만으로 실사용 해결을 판정하지 않는다.

### 현재 상태

추가 원인 진단과 실패 루프 구성 중이다.
목적별 실제 적용 기능의 내부 구현을 작성했으며 제품 화면에는 연결하지 않았다.
최초 미구현 상태의 단언 4개 실패를 확인한 뒤 구현자 검사에서 편집 5건·준비 상태 2건·앱 연결 7건이 통과했다.
독립 정적 검수에서 적용 기록 수명과 실제 해석값 전후 기록의 보완을 요청했고 구현자가 반영했다.
고정 커밋 `d4722d2`의 독립 편집·준비 7건과 기존 앱 7건은 통과했다.
독립 검수자가 추가한 분석 갱신 반례 1건은 단언 2개가 실패했다.
동일 사진을 다시 분석한 뒤에도 이전 적용 완료 상태가 남는 결함은 `03957de`에서 수정했다.
독립 검수에서 앱 회귀 9건과 같은 독립 반례 1건이 모두 통과해 내부 적용 기능만 좁게 승인했다.
변경 없는 패키지 7건의 통과 근거를 유지하며 UI·사용자 사진 품질·배포는 승인 범위가 아니다.
이는 사용자 사진의 보정 효과 부족 원인을 확정한 결과가 아니다.
새로운 품질 수용 및 후속 배포는 아직 수행하지 않았다.

### 첫 실행과 재현 한계

별도 QA 타깃의 `PortraitDisplayReplayTests`를 Mac에서 실행했다.
입력은 사용자 화면의 사진 부분을 분리한 563×750 표시용 이미지이며 고해상도 원본이 아니다.
실제 AppModel → Vision → 원터치 강도 1 → 렌더 경로에서 얼굴 1명과 적용 대상 1명을 확인했다.
사전에 정한 좌상단 배경 영역의 4레벨 이상 변화율은 0이었다.
색·디테일·배경·효과·얼굴형·체형 레시피는 그대로였고 원본/보정본 표시가 해당 이미지 객체에 연결되었다.
검사 1개는 3.559초에 통과했다.
로그는 `/tmp/portrait-display-replay-first.log`다.
이는 새 편집 상태와 축소 입력에서 큰 배경 변화를 재현하지 못했다는 결과이며 피부 개선이나 사용자 증상 해결을 의미하지 않는다.
표시 강도와 실제 여성·개인 층까지 해석한 값은 구분해서 기록한다.

제공된 두 화면을 같은 crop `(308, 567, 563, 750)`과 같은 좌상단 85×150 영역으로 비교하면 RGB 최대 차이 4 이상인 픽셀은 12,384/12,750, 즉 97.1294118%다.
같은 기준의 새 AppModel 재현 결과는 0.0%다.
따라서 배경 영역 선택이 변화 없는 곳이어서 증상을 놓쳤다고만 설명할 수 없다.
측정 스크립트와 숫자는 `/private/tmp/mellow-portrait-display-replay/`에 보존하며 원본·파생 이미지는 Git에 포함하지 않는다.

확인할 가설과 예측은 다음 순서다.

1. 저장 레시피·최종 개인 값과 표시가 다르면, 읽기 전용 계측에서 새 재현과 다른 색·배경·개인 키가 확인된다. 사용자가 다른 기능을 조작했다는 가정은 포함하지 않는다.
2. 비교·미리보기의 사진 또는 렌더 세대가 다르면, 사진과 레시피의 식별 정보가 맞지 않으며 사진 A→B→A와 처리 중 전환 검사로 구별된다.
3. 원본 해상도·기기·Release 처리 경로가 다르면, 같은 원본·레시피의 분석 마스크나 출력에서 환경별 차이가 확인된다.

원본 사진은 이후 수신했으나 당시 실제 레시피는 확인되지 않았고 아직 어느 가설도 확정하지 않는다.

### 목적별 실제 적용안: 독립 설계 검토 중

| 목적 | 값의 출처 | 적용 조건 |
|---|---|---|
| 피부 정리 | 기존 피부 원터치의 유효 성별 표 × 강도, 기본 0.6·상한 1 | 피부 보정용 실제 특징점·마스크, 눈입·색조·형태는 목적 밖 |
| 턱밑 정리 | 기존 이중턱 강도 1의 검증점, 새 증폭 없음 | 실제 턱 특징점·마스크와 좌표 유효, 형태 잠금 아님 |
| 옆선 정리 | 기존 부유방 강도 1의 검증점, 새 증폭 없음 | 개인 대상, 실제 몸-얼굴 연결과 옆선·마스크 유효, 형태 잠금 아님 |

- 기존 값 초기화를 허용하기 위한 `canAdjust` 예외를 새 효과 적용 가능성으로 사용하지 않는다.
- 사람과 키마다 최종 해석값의 전후와 미적용 이유를 계획에 포함한다.
- 개인의 기존 명시값은 기본적으로 보존하며 사용자의 명시적인 교체 선택만 덮어쓴다.
- 실제 변경이 0이면 이력·저장·완료 표시를 만들지 않는다.
- 여러 사람·키의 변경도 한 번의 트랜잭션과 undo/redo로 묶으며 같은 값 재적용은 no-op이다.
- 사진·레시피·분석이 달라진 계획은 적용하지 않는다.
- 성별을 자동 지정하거나 미검출 영역 대신 다른 사람·부위를 사용하지 않는다.
- 피부 전용 적용을 기존 전체 원터치 강도로 표시하지 않는다.
- 기하 정보의 존재와 제거할 결함의 존재를 구분한다.
- 이 안을 구현해도 현재 사용자 사진의 원인 진단·품질 수용은 별도로 남는다.

### UI 노출 전에 필요한 교차 검증

목적별 적용으로 개인 층에 생긴 키는 이후 기존 전체 원터치의 값을 가릴 수 있다.
개인 값 보존은 유지하되 전체 강도 표시를 각 사람의 실효 강도처럼 표현하지 않는다.
목적 적용 결과의 출처를 추정해 기존 개인 키를 자동 삭제하지 않는다.

- 목적 피부 0.6 후 전체 원터치 1과 0.
- 전체 원터치 1 후 목적 피부의 보호 적용과 명시적 교체 적용.
- 그룹 강도 변경과 개인 명시값 0·비영 값이 섞인 경우.
- 각 경우의 실제 해석값, 변경·보호·적용 불가의 사람과 키를 확인한다.
- 실제 적용 결과 표시의 수명은 사진·레시피·처리 요청 세대에 묶으며 undo·사진 전환 후 이전 성공 표시를 남기지 않는다.

이 항목은 미노출 core 검수와 별개로 향후 UI 수용의 필수 조건이다.

### 추가 품질 prototype의 한계

표시용 crop과 고정 Vision 결과에 심은 결함을 쓰는 별도 실험에서는 실제 원터치의 회복 지표 0.8554, 미세 대역 분산비 0.70735가 나왔다.
실제 밝기·대비·피부 톤·입술·흐림 대조는 이 prototype의 결합 조건에서 거절됐다.
그러나 0.85라는 기존 상수를 재사용했더라도 ROI의 이진 선택·점 주변 제외·표시 크기·출력 양자화가 기존 원 검사와 다르다.
독립 검수에 따라 이 결과는 추가 보호 경고로만 남기며 기존 정식 수용검사 위반이나 사용자 원본 손상을 확정한 결과로 사용하지 않는다.
기존 회복 기준도 해당 목적과 강도에 맞게 연결해야 하며, 단독 강도 1의 팔자 회복 하한을 낮은 강도의 묶음에 그대로 적용하지 않는다.

### 검증 범위와 다음 인계

내부 검사는 목적 적용의 값·보호·실행 취소·저장·미리보기 연결을 확인한다.
일반 사진에서 잡티·주름·턱밑이 충분히 정리되었다는 사용자 품질 수용과 구분한다.
최종 사용자 답변은 '원터치 보정만 누름'이며 추가 조작을 가정하지 않는다.
사용자가 동일한 보정 전 원본은 iPhone 사진 앱에만 있다고 확인했다.
해당 사진 한 장을 전송하도록 안내한 뒤 사용자가 원본 사진을 첨부했다.
수신 JPEG는 저장 크기 4032×3024·Display P3·EXIF 방향 6이며 방향 보정된 입력은 3024×4032다.
수신 파일의 실제 AppModel·Vision·원터치·미리보기/내보내기 Mac 재현과 독립 읽기 검수를 완료했다.
iPhone의 별도 QA 앱에서 동일 원본·새 편집 상태 재현을 완료했다.
사용자는 문제 사진이 그때 처음 불러온 사진이 아니라 이전부터 앱에 불러둔 사진이었다고 추가 확인했다.
당시 저장값이나 다른 조작의 존재·내용은 추정하지 않는다.
기존 앱과 사진은 유지하며 후속 버전 배포·UI 노출은 보류한다.

### 원본 확보 후 같은 증상 재현 절차

1. 사용자가 지정한 보정 전 사진 한 장만 별도 로컬 QA 입력으로 사용한다. 원본은 덮어쓰지 않는다.
2. 방향·해상도·색 공간과 디코드된 입력 식별값을 기록하고 원본/미리보기/내보내기 비교가 같은 사진을 가리키는지 확인한다.
3. 새 편집에서 실제 원터치 버튼 한 번을 적용해 전체·그룹·개인의 해석값, 색·배경 키, 렌더 요청 식별값을 함께 기록한다.
4. 사용자 보고와 다른 결과이면 당시 선택 사진의 편집값만 확인할 방법을 마련한다. 전체 앱 컨테이너나 다른 사진을 수집하지 않는다.
5. 같은 레시피로 iPhone 미리보기와 내보내기를 비교하고 색 변화·배경 변화·피부 결함 개선·정상 질감 보존을 분리한다.
6. 실패 재현이 고정된 뒤 한 원인씩 수정하고 독립 검수자가 같은 입력·기준으로 확인한다.

피부 목적 core 추가를 이 절차의 대체 수정으로 간주하지 않는다.
원본을 실제로 수신하기 전에는 이 절차를 수행했다고 기록하지 않는다.

### 수신 원본의 첫 실제 앱 재현

같은 live 조립(Vision 얼굴·사람·몸·개별 사람 분석, 실제 룩·메이크업 카탈로그, 기기별 튜닝)으로 원본 사본을 가져왔다.
화면에 확인된 여성 1명·전체 대상을 준비하고 원터치 강도 1만 적용했다.
Mac 미리보기는 1200×1600, 실제 앱 PNG 내보내기는 3024×4032였다.
얼굴 1개·특징점 영역 12개를 찾았고 피부 마스크가 존재했으며 최종 여성 층의 smoothing 0.2·spots 1을 확인했다.
색·디테일·배경·효과·얼굴형·체형 레시피는 바뀌지 않았고 실행 취소는 한 단계였다.
원본/미리보기 비교 표시가 각각 올바른 이미지 객체를 가리켰다.
고정 배경 영역의 RGB 최대차 4 이상 변화율은 미리보기와 내보내기 모두 0이었다.
얼굴 영역 RGB 변화율은 각각 약 37.28%·37.19%이며 이것을 자연 결함 개선이나 품질 수용으로 해석하지 않는다.
검사 1건은 17.696초에 통과했지만 사용자 화면의 강한 명암 변화·배경 흐림은 재현하지 못했다.
로컬 전후 출력에서는 볼 질감 완화가 보이나 사용자가 기대한 윤곽 보정의 완성을 의미하지 않는다.

다음 최소 조사 순서는 동일 원본·레시피의 iPhone 경로, 실제 선택 사진의 제한된 편집값 계측, 비교/렌더 요청 식별값 불일치 확인이다.
기기 등록·별도 QA 검사·기존 앱과 사진 보존에 대한 기존 사용자 승인은 유지되므로 반복 허가를 요청하지 않는다.
현재 연결·잠금 상태는 실행 직전 확인하며 실제 오류가 없는 상태에서 잠금 해제를 요구하지 않는다.
현재 개인 앱 전체 컨테이너나 다른 사진을 수집하지 않는다.


원본 Mac 독립 검수에서 입력·출력·레시피의 해시 연결과 실제 조립은 일치했다.
배경 표본은 전체 배경이 아닌 좌상단 15%×20% 영역이며, 독립 sRGB8 디코드의 최대 차이는 1/255였다.
전역 color 레시피 불변과 피부 톤·눈입·메이크업·몸 피부 밝기 불변은 다르다.
이번 원터치는 후자 항목 일부를 실제로 바꾸므로 얼굴 RGB 변화율을 피부 정리 품질로 해석하지 않는다.
얼굴 사각형 좌표가 첫 보고에 없어 얼굴 변화율의 독립 재집계는 하지 못했다.
iPhone 재현 보고에는 얼굴 좌표·최종 전체 해석값·분석 준비 키·몸 연결·완료 세대·OS·튜닝·색 공간을 포함한다.


### iPhone 원본 재현과 현재 조사 경계

기존에 승인·등록된 iPhone 15 Pro에서 별도 QA 앱의 지정 검사 한 건을 실행했다.
설치 직전 독립 검수는 별도 앱 식별자·서명·해당 기기·격리 시작 경로·사용자 원본 사본 한 장의 해시를 확인했다.
실행 단계의 실제 잠금 오류가 발생해 한 번 잠금 해제를 요청했고 사용자의 응답 후 같은 실행에서 정상 진행했다.
검사는 22.031초에 통과했으며 QA 결과 8개 파일만 로컬로 회수하고 소유 앱·검사 프로세스 종료를 확인했다.
제품 앱은 1.6.0 (13.1)이 설치되어 있으나 이번 검사는 03957de Debug의 새 편집 상태 API 경로다.
따라서 사용자 제품의 Release·과거 저장값·native Canvas 전체 재현과 같다고 주장하지 않는다.

실기기 미리보기는 900×1200, PNG 내보내기는 3024×4032였다.
실기기 물리 메모리 8053047296바이트는 코드의 8GiB 경계보다 작아 미리보기 상한 1200을 사용했다.
원터치 최종 피부 값은 smoothing 0.2·spots 1, 개인 덮어쓰기 키는 없었다.
같은 레시피의 직접 렌더와 표시 미리보기는 byte 단위로 일치했고 원본/미리보기 비교 객체도 일치했다.
고정 좌상단 배경 표본의 RGB 최대차 4 이상 변화율은 미리보기·내보내기 모두 0이었다.
자연 피부 품질 수용은 여전히 별도다.
피부 및 턱밑 준비 키는 존재했으나 유효 몸과 얼굴-몸 연결이 없어 옆선 준비 키는 없었다.

현재 전체·그룹 원터치는 기존 전역 색·배경과 개인 명시값을 보존한다.
기존 사진의 저장·복원 상태에서 표시 강도와 최종 개인 적용값이 달라지는 경로를 별도 최소 입력으로 검사한다.
이 재현이 성공하더라도 실제 사용자 사진에 어떤 값이 저장됐는지 확인한 결과로 쓰지 않는다.
실제 제품의 저장 설정을 확인하는 방법은 최소 범위를 준비하는 단계이며 제품 컨테이너·설정 파일 조회·복사는 아직 승인 범위를 확대해 수행하지 않았다.


### 저장 상태 최소 재현 및 제한된 진단 준비

사용자가 이전부터 앱에 불러둔 사진이었다고 확인한 뒤, 합성 입력의 실제 AppModel 저장·복원 3가지 경우를 한 검사로 실행했다.
개인 피부 키 전체가 명시적으로 0 또는 비영 값이면 전체 강도 1·대상 1명·공통 smoothing 0.16이 표시돼도 최종 개인 값 0 또는 0.67과 해당 출력은 유지됐다.
일부 키만 개인 값 0이면 그 키는 유지되고 다른 키만 바뀌었다.
기존 전역 색·배경은 세 경우 모두 유지됐다.
이것은 기존 계약의 실제 동작 재현이며 사용자 사진의 저장값을 확인한 결과가 아니다.
초기 검사에서 렌더 값과 표시용 oneTouch 메타데이터를 함께 동일하다고 비교한 두 단언은 분리해 수정했으며 원로그를 보존했다.

실제 앱의 설정은 단일 session.json에 모든 사진의 현재 레시피·undo/redo·이름·파일명·선택 ID·프리셋을 담는다.
기기 도구에는 JSON 선택자 필터가 없어, 선택 사진만 진단하려 해도 전체 설정 파일 바이트를 잠시 받아야 한다.
그래서 기존 별도 QA 검사보다 넓은 읽기 범위를 사용자에게 설명하고, 문제 사진 선택 후 해당 설정 파일 한 개를 읽어도 되는지 확인을 요청했다.
이후 사용자는 어느 기기에서 선택해야 하는지 물으며 가능한 작업은 직접 하라고 지시했다.
iPhone의 Mellow 앱을 뜻한다고 설명했고, 같은 제한 범위의 대상 선택·설정 읽기를 직접 진행하도록 구현자 역할을 재개했다.
사진 선택은 실제 화면에서 해당 사진임을 확인한 뒤에만 수행하며 보정값 변경·초기화·새 가져오기는 포함하지 않는다.
실제 설정 접근과 진단 결과는 다음 실행 근거로 별도 기록한다.

준비된 순수 추출기는 schema 2·명시된 선택 ID의 유일한 일치만 허용하며 현재 recipe와 undo 마지막 한 개만 출력한다.
redo·사진 이름·파일명·다른 사진 설정·프리셋은 출력하지 않는다.
새로 만든 소유 임시 폴더는 0700, 출력은 0600이며 전체 설정 사본은 정상·내용 오류·전송 오류·사전 검사 실패에서 제거한다.
독립 검수의 합성 검사 11건이 통과했으며, 실제 실행은 검수한 상위 정리 함수를 반드시 사용한다.
저장된 선택 ID가 화면의 현재 선택과 동일하다는 보장은 없으므로 선택 저장 실패나 지연도 고려한다.
원본 사진 파일 조회·복사, 제품 데이터 변경, 외부 전송은 이 진단 범위에 포함하지 않는다.


### 실제 저장 상태로 확인된 결함과 후속 수정 계약

사용자의 직접 수행 지시 후 iPhone의 실제 Mellow 화면에서 제공된 밤 셀카가 이미 선택돼 있음을 확인했다.
사진 선택이나 보정값을 조작하지 않고 승인된 설정 파일 한 개를 검수된 소유 임시 폴더 경계로 읽었다.
선택 사진의 현재 레시피와 undo 한 개만 추렸고 전체 설정 임시 사본은 즉시 삭제했다.
독립 검수는 화면·인물 anchor와 제공 원본 분석의 일치, 최소 수집·삭제, 전후 값과 해석 우선순위를 확인했다.

직전 저장 상태에서 전체 원터치 강도는 0.6에서 1로 바뀌지만 개인 원터치 약 0.20은 유지된다.
개인 층이 피부·눈입·메이크업 키를 모두 덮어써 최종 얼굴 보정값은 그대로이고 몸 피부 밝기만 0.048에서 0.08로 증가한다.
기존 전역 노출·야간 룩·배경 흐림도 전후 동일하다.
이전 설정이 생긴 시점이나 사용자 행동은 추정하지 않는다.
캡처 당시 처리 표시가 있어 그 화면을 완료 렌더의 증거로 사용하지 않는다.
제공 원본과 실제 두 레시피를 같은 로컬 렌더러로 복원하는 후속 재현으로 픽셀 결과를 별도 확인한다.

수정은 렌더 강도를 증폭하지 않고 적용 우선순위와 표시/실행 계약을 바로잡는다.

- 전체·그룹의 기존 기본 동작은 개인 명시값을 보존한다. 직접 선택한 개인 대상은 기존처럼 그 개인 묶음을 재적용한다.
- 대상별 보고는 전체/그룹의 표시 강도와 실제 각 인물의 변경 키·유지된 개인 키를 구분한다.
- 얼굴 값이 하나도 바뀌지 않은 경우 인물 보정 완료로 표현하지 않는다. 전역 몸 피부 밝기 변화와 얼굴 변화를 구분한다.
- 사용자가 명시적으로 선택할 수 있는 '개인 조정도 이 강도로 적용' 동작을 별도로 제공한다. 반복 확인창 없이 한 번의 명시적 조작이다.
- 명시적 교체는 현재 선택된 실제 인물의 원터치 묶음 키만 바꾼다. 다른 사람·찾지 못한 기록·얼굴형·체형·수동 지역 조정·전역 색/룩/배경은 유지한다.
- 그룹 대상은 현재 해석된 해당 성별의 인물만, 개인 대상은 해당 한 명만 다룬다. 성별 자동 지정과 이웃 인물 대체는 하지 않는다.
- 여러 명의 교체도 한 트랜잭션/undo로 묶고 같은 값 재적용은 이력·저장 중복을 만들지 않는다. undo/redo와 저장·복원 후 보호 항목과 실제 개인값을 모두 확인한다.
- 강도 0의 명시적 교체/해제 계약은 기존 0 동작과 구분해 테스트로 고정한다. 명시되지 않은 개인 조정이나 다른 인물 기록을 지우지 않는다.
- 사진·대상·분석·레시피가 바뀐 오래된 적용 계획이나 완료 상태는 재사용하지 않는다.
- 공개 회귀 검사는 합성 입력으로 같은 호출 흐름을 검증하고 실제 사용자 레시피·좌표·사진은 Git이나 원격 검사에 포함하지 않는다.
- 우선 내부 적용과 회귀·독립 검수를 완료하고, 실제 원본의 동일 상태 재현 및 기존 보존/효과 검사를 통과한 범위만 UI에 연결한다.

실제 iPhone의 사용자 편집값은 진단 후에도 그대로 유지한다.


### 원터치 교체 구현 세부 계약 확정

기존의 강도 0은 선택 층의 키를 지워 상속으로 돌아가는 별도 동작으로 유지한다.
새 명시적 개인 교체의 강도 0은 원터치 묶음의 중립 0·false·강도 0 메이크업을 개인 층에 명시해 상속을 차단한다.
이미 최종 실효값이 같다면 새 키·기록·표시용 강도만 추가하지 않으며 저장·이력을 만들지 않는다.
강도 0의 메이크업 색 이름 차이처럼 렌더에 영향 없는 메타데이터도 효과 변화로 세지 않는다.
검출 인원이 없는 그룹의 기존 원터치 값을 지우는 예전 강도 0 경로는 새 적용의 no-op 정책에 흡수하지 않는다.

기본 보호 적용은 기존 원터치 proposal을 만들고 실제 매칭 인물의 준비된 최종 값과 유효 몸 피부 변화가 전혀 없으면 폐기한다.
표시용 marker나 찾지 못한 사람의 숨은 값 변경만으로 저장·이력을 만들지 않는다.
하나의 얼굴에서 준비되지 않은 항목 때문에 다른 얼굴의 기존 적용을 막는 전역 준비 키 교집합 정책은 도입하지 않는다.
일부 준비된 효과가 바뀌어 기본 proposal을 저장할 때에는 다른 미준비 항목의 설정값도 기존 계약대로 저장될 수 있다.
따라서 결과는 저장값 변경·현재 렌더 준비가 된 변경·현재 렌더 준비 불가를 구분하고, 준비 불가를 모두 미저장이라고 표현하지 않는다.
명시적 개인 교체는 준비된 선택 인물 키만 쓰므로 그 경로에서 미준비 키는 보존한다.
피부·눈·치아·입·블러셔 등은 각각 실제 렌더의 마스크·특징점·카탈로그 근거로 준비를 판단하며 기존 피부/턱밑/옆선 목적 키 목록을 다른 부위의 준비 증거로 재사용하지 않는다.

향후 UI는 요청 강도와 저장된 강도 표시를 분리한다.
개인 설정에 전부 가려져 기본 proposal이 폐기돼도 사용자가 요청 강도를 선택해 명시적 교체를 실행할 수 있어야 한다.
요청 강도를 저장 marker에만 묶어 슬라이더가 이전 값으로 되돌아가게 만들지 않는다.

### 실제 상태 재현과 최초 인물 적용 회귀

제공 원본과 현재 설정을 복원하고 한 단계 되돌린 뒤 기존 원터치를 다시 실행했다.
현재 저장 레시피와 재적용 레시피가 같았고 두 렌더 출력도 파일 및 디코드 픽셀 기준으로 같았다.
얼굴의 최종 설정이 같아도 몸 피부 밝기 처리 때문에 일부 얼굴 픽셀은 달라질 수 있으므로 설정 불변과 픽셀 불변을 구분한다.
개인 설정의 생성 경위는 확인하지 않았다.
원본과 개인 설정 및 파생 결과는 로컬 임시 검사 폴더에만 두고 공개 회귀에는 합성 입력만 사용한다.

원터치 보고 코어의 독립 검수에서 개인 기록이 없는 얼굴의 최초 기본 적용이 잘못 거절되는 반례가 나왔다.
최초 적용이 만든 단일 사람 기록의 식별자와 의도한 얼굴 연결만 추적하도록 보완했다.
기존 사람 및 찾지 못한 기록의 보존 검사와 최종 얼굴 연결 검사는 유지한다.
수정본 `7851048`은 구현자 도메인 9건과 앱 8건이 통과했다.
독립 검수에서도 도메인 9건·기존 독립 반례 1건·준비 조건 2건 및 앱 18건이 통과해 내부 코어 범위를 승인했다.
렌더 수치가 바뀌지 않아 기존 효과·보호 수용 기준은 유지한다.
실제 사진의 명시적 교체 출력은 별도 로컬 검사와 독립 검산을 완료했다.
전체·그룹의 기본 요청은 개인값 보호로 변경 없이 끝났고 명시적 교체는 준비된 얼굴 항목 13개만 바꿨다.
다른 색·배경·형태 설정, 실행 취소·재실행·저장 복원을 보존했다.
이 근거로 좁은 UI 연결 구현을 승인했으며 자연 피부 품질 전반이나 최종 배포 수용을 대신하지 않는다.
UI 수정본 `16bdd79`는 구현자 관련 앱 검사 120개와 iOS UI 타깃 빌드 및 Mac Release 빌드를 통과했다.
실제 UI 실행은 아직 없으며 독립 소스·회귀 검수 뒤 별도 합성 검증 앱으로 확인한다.

### UI 연결 수용 조건

빠른 보정과 뷰티의 원터치 줄은 같은 적용 보고 API와 상태 표현을 사용한다.
요청 강도는 현재 사진과 실제 대상별 입력 상태로 관리하며 저장된 마지막 강도나 완료 결과로 오인시키지 않는다.
전체·그룹의 기본 버튼은 개인 조정을 유지하며 실제로 유지된 개인 조정이 있으면 그 사실을 즉시 표시한다.
직접 선택한 개인 대상의 기본 버튼은 그 사람의 원터치 묶음을 재적용함을 명시한다.
선택 대상의 준비된 개인 원터치 항목을 교체하는 버튼은 `개인 조정도 이 강도로 적용`처럼 행동을 명시한다.
얼굴 변경 없이 몸 피부 밝기만 바뀐 결과는 얼굴 보정 완료로 표시하지 않는다.
완료 문구는 저장과 해당 렌더의 완료 이후에만 표시하고 처리 중·실패·변경 없음·분석 불가를 구분한다.
대상이나 사진을 바꾸면 이전 대상의 결과가 새 대상의 완료처럼 남아 있지 않아야 한다.
기존 빈 성별 그룹의 강도 지우기와 되돌리기를 유지한다.
사용자의 실제 사진 설정을 자동으로 교체하거나 초기화하지 않는다.

슬라이더는 드래그 중 요청값만 갱신하고 종료 시 기본 적용을 한 번 실행해 한 번의 실행 취소를 유지한다.
새 convenience API를 매 프레임 호출해 각 프레임을 별도 저장하는 방식은 사용하지 않는다.
빠른 보정의 고정 전체 대상은 뷰티의 현재 선택과 다를 수 있으므로 실제 행동 대상별 요청값과 결과를 연결한다.
사진 A→B→A·패널 왕복·얼굴 재매칭에서도 다른 대상의 입력이나 완료 결과를 섞지 않는다.
변경 없음이나 보호됨을 새로 시도하면 직전 성공 완료를 현재 시도의 성공처럼 남기지 않는다.
사용자에게 보이는 시도 결과와 실제 저장·렌더 완료 기록의 수명을 분리하고 실행 취소·재실행·수동 편집·재분석에서 무효화한다.
개인 기록의 존재만으로 보호 여부를 추정하지 않고 실제 매칭 대상의 보호된 키와 준비된 변경 인원을 사용한다.
패널을 여는 동작은 사람을 선택하는 동작으로 설명하지 않는다.
